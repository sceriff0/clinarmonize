§0The invariant everything else serves

Docs Book of OHDSI — data quality OMOP CDM v5.4 Nextflow — channels

Outcome-Blind Mapping

No harmonization decision — column match, value mapping, unit conversion, endpoint derivation, or linkage threshold — may be a function of the outcome variable.

A leak at the value level is caught by cross-validation. A leak in the schema is not: by the time a model sees the data, the leak is the column definition, and every honesty check downstream runs against columns that already know the answer. The tempting move — try both response codings, keep the one with the cleaner survival split — is label leakage wearing a data-cleaning costume.

§0.1The falsification test

# Permute the outcome within each cohort. Re-run the proposer. Hash the ledger.
nextflow run . -profile test,docker --permute_outcome_seed 1..100 --stop_after propose
sha256sum results/ledger.proposed.yaml   # must be identical for all 100

# Any difference is a schema-level leak. Not a warning — a build failure.
# The pack's `outcome: true` flag is what the test keys on, so the invariant
# binds whatever THIS pack calls an outcome, never a hard-coded column name.
# That is what lets one test defend an oncology run and a critical-care run.

§0.2Build protocol for the implementing agent

Nextflow docs nf-core pipeline guidelines

For each step, in ladder order:

1. Read §0 (the invariant) and this step's card. Read nothing else.
2. Write the failing test from `done` FIRST. Confirm it fails.
3. Fetch the `docs` links. Your training data is stale; the pins are not.
4. Implement to `contract`, at the paths `contract` names. Nothing more.
5. Honour `nogo`. Absent instruction is not licence.
6. Every `params` row becomes a nextflow_schema.json property with that
   exact default. No magic numbers in code.
7. Build behind the `alts` seam even when only one alternative exists today.
8. Run the `done` command. Output must match. Stop; do not begin the next step.

§1Ingest — the two-level samplesheet and the holdout seal

Docs nf-schema — samplesheet schema Nextflow — channel operators JSON Schema

Two levels, because the data has two levels: a cohort holds many datasets, and the JOIN happens inside a cohort while the UNION happens across them. A flat sheet cannot express that difference, so a flat sheet makes §0.3's conflation the default.

  1. §1.1Validate the two-level samplesheet into a typed channel

    Why

    The samplesheet is the pipeline's own entry point, not a handshake with an upstream tool (principle 5). Validating it here means every later stage can assume a cohort id, a dataset role and a holdout flag exist, and no later stage needs a null check.

SIDE fails fast on duplicate (cohort_id, dataset_id); writes no files

  2. §1.2Drop held-out datasets at channel construction, not at read time

    Why

    A held-out dataset that reaches a process can be read by a bug. One that was never emitted into the channel cannot. Moving the seal from runtime to graph construction turns "we did not look" from a promise into a property of the DAG.

§2Profile — the column evidence record

Docs DuckDB Polars Arrow — Parquet Book of OHDSI — data quality

The profile is the only thing the matcher ever sees. A channel whose evidence the profiler did not capture is not a weak channel — it is a dead one, and it fails by scoring every candidate equally, which reads as "no strong match" rather than as a bug.

  1. §2.1Profile every column into a typed evidence record

    Why

    Every downstream evidence channel reads exactly one field of this record. Fixing the record's shape here fixes what the matcher is capable of noticing, so the field list is a design decision about detection power, not a convenience.

    I/O 
    IN   [ meta(cohort_id, dataset_id), path(table) ]

SIDE none — a pure function of the table bytes and the params below

§3Link within a cohort — probabilistic record linkage

Docs splink Fellegi–Sunter model blocking rules DuckDB

This is the JOIN half of §0.4, and it is the half that changes N. Over-linkage merges distinct patients and N shrinks; under-linkage splits one patient and N inflates. A model downstream cannot tell them apart, so the only place either is visible is here.

  1. §3.1Block candidate pairs so comparison is tractable

    Why

    Comparing every pair is quadratic and unnecessary. Blocking is where the recall ceiling is set: a pair excluded by every blocking rule can never be matched, no matter how good the comparison model is, and no later stage can tell it was excluded.

    IN   a cohort's datasets, one row per patient-record

SIDE none

- id: br_name3     on: [substr(last_name,1,3), birth_year]
- id: br_mrn       on: [mrn]

  2. §3.2Score pairs with a Fellegi–Sunter model, missing as its own outcome

    Why

    m and u — agreement given the same person, agreement given different people — turn field comparisons into a log-likelihood ratio that is comparable across fields. Everything about the linkage's honesty lives in whether those two probabilities were estimated or assumed.

    I/O 
    IN   candidate pairs + the cohort's records
OUT  link/scores.parquet  (left_id, right_id, match_weight, per_field_agreement)

SIDE none

match_weight = log2( P(pattern | match) / P(pattern | non-match) )
             = sum_over_fields log2( m_f(level) / u_f(level) )

§15Decision log

ADR-001The target variable set is a runtime concept pack, not a baked-in schemaaccepted

context The first design named an ICS/ICI-specific extension to the CDM subset. That made the pipeline an oncology tool with a general-sounding name.

decision The pack — a hashed YAML asset — declares every target variable, its domain, its concept id, its type and whether it is an outcome. Shipped packs live at assets/packs/*.yaml; --concept_pack takes any path or URL, so a private pack never enters the repo.

consequence Generality becomes checkable (§10.3) rather than claimed, and the invariant binds whatever this pack calls an outcome. Cost: nothing in the pipeline can be written knowing what a variable means.

ADR-002The pipeline proposes; it never decides a mappingaccepted

context A matcher confident enough to auto-map is confident enough to be wrong invisibly, and its confidence is exactly where outcome leakage would hide.

decision §4 emits a ranked ledger with a per-channel evidence vector and a confirmation plot per proposal. §5 requires a human-confirmed ledger file. Auto-confirm exists only under -profile test.

consequence A real run cannot complete unattended the first time. That is the point: the gate is a file, so the decision is auditable, diffable in review, and the rerun deterministic — none of which a GUI prompt would give.

ADR-003The invariant harness scopes to the proposer, not the whole pipelineaccepted

context §8.3's standardized-difference forest legitimately reads outcome variables — it is reporting, not a mapping decision. An end-to-end permutation test would fail on it.

decision invariant_scope defaults to propose. Widening it is a design change requiring a superseding ADR, not a config edit.

consequence The test stays true, so it stays enabled. The residual risk is a leak entering after §4 — which §12's checklist and the confirm gate are the compensating controls for. Reviewed at the phase-3 gate.

ADR-004Held-out data is a per-dataset setting with a lock, not a one-time ritualaccepted

context The predecessor design named one cohort and described unsealing it as a documented human ceremony. A ceremony is not enforceable and a log-only record reports the violation after the damage.

decision holdout is a samplesheet boolean; held-out rows are dropped at channel construction; --unseal <id> refuses unless locked_model.json exists and its hash matches the analysis about to run, then appends to unseal.log.

consequence The lock enforces the ordering — freeze first, then look — which a log alone cannot. One mechanism serves every pipeline in the stack.

ADR-005Missingness is classified and reported here; imputation happens downstreamaccepted

context Imputing inside the harmonizer would produce one convenient artifact, and would bake an assumption into the canonical output that every consumer silently inherits.

decision §8.2 emits a per-cohort, per-variable class (systematic, near-systematic, sporadic, complete) and the heatmap. It imputes nothing.

consequence Consumers must choose a strategy and defend it. A systematically missing variable cannot be imputed within a cohort by accident, because the class says so in the output.

ADR-006A five-table CDM subset plus an extension, not full CDM conformanceaccepted

context Full OMOP conformance is a large ETL for a pipeline whose consumers need five tables and a set of derived endpoints. Forcing derived endpoints into observation would be nominally conformant and semantically wrong.

decision Emit person, condition_occurrence, drug_exposure, measurement, observation, plus _extension/<pack>.parquet. Never claim full conformance.

consequence OHDSI tooling works on the subset; the extension needs the pack to interpret. Revisit by ADR if the ETL outgrows one phase.
