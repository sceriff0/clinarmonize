# §4.3 — Write the ranked proposal ledger, deterministically

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

The ledger is what the invariant is tested on. Byte-level determinism given identical inputs is not tidiness — it is the precondition for the permutation test in §10.1 meaning anything at all.

## I/O

```
IN   propose/evidence.parquet
OUT  ledger.proposed.yaml    ordered, stable, hashable
SIDE none; identical inputs MUST yield an identical sha256
```

## Contract

```
# ledger.proposed.yaml — sorted by (cohort_id, dataset_id, column, -total)
- cohort_id: COHORT_A
  dataset_id: clinical
  column: "PDL1_PCT"
  proposals:
    - variable: pdl1_tps
      concept_id: 4245277
      total: 0.87
      evidence: {name: 0.62, type: 1.0, card: 0.9,
                 value: 0.95, dist: 0.71, unit: 1.0}
      confirmation_plot: propose/confirmation_plots/a.clin.PDL1_PCT.png
      excluded_candidates: 3        # the recall ceiling, made visible
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| ledger_top_k | 5 | 1..50 | proposals written per column; the rest are counted, not listed | config |
| ledger_float_precision | 4 | 2..8 | rounding, so a float's last bit cannot change the hash | config |
| permute_outcome_seed | null | int or range | test-only: permutes the outcome to falsify the invariant | CLI |

## Alternatives

Seam: LedgerWriter — write([Proposal]) -> bytes

| alternative | why you'd swap | swap cost |
|---|---|---|
| JSON Lines | streams; diffs line-wise in review | far less readable for the human at the §5 gate, who is the actual audience |
| a database table | queryable across runs | not hashable, not diffable, not reviewable in a pull request |

## Trap

Non-determinism from map iteration order or unrounded floats. It makes every permutation hash differ, so the invariant test reports a leak on every run and gets disabled — the failure mode is a switched-off gate, not a red build.

## Not here (nogo)

Do not write a timestamp, hostname, absolute path or run id into this file. Never promote a top proposal to confirmed — that is §5 and it requires a human.

## Done when

```
for s in 1 2 3; do nextflow run . -profile test,docker \
  --permute_outcome_seed $s --stop_after propose; \
  sha256sum results/ledger.proposed.yaml; done | sort -u | wc -l
```

That prints 1. Three permutations, one hash.
