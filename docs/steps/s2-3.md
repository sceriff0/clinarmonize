# §2.3 — Manifest unprofilable columns instead of dropping them

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

A column that failed to parse is the most informative column in the table: it is where the source data disagrees with every assumption. Dropping it silently converts a finding into a coverage number nobody can explain.

## I/O

```
IN   profiling failures (encoding, mixed type, unreadable)
OUT  profiles/_failed.json  [{cohort_id, dataset_id, column, reason, sample}]
SIDE exit non-zero when the failure RATE exceeds --max_failed_frac
```

## Contract

```
{ "cohort_id": str, "dataset_id": str, "column": str,
  "reason": "encoding|mixed_type|unreadable|all_missing",
  "sample": [str] }        # first k offending raw values, verbatim
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| max_failed_frac | 0.05 | 0.0..1.0 | above this fraction of columns, the run fails rather than reports | config |
| fail_sample_k | 3 | 0..20 | offending values carried into the manifest | config |

## Alternatives

Seam: FailurePolicy — onFail(column, reason) -> skip | fail

| alternative | why you'd swap | swap cost |
|---|---|---|
| fail on the first bad column | strictest; nothing slips through | unusable on real clinical exports, which always have one junk column |
| quarantine to a side table | keeps raw values for later rescue | a second output path and a PII question nobody has answered |

## Trap

Treating an all-missing column as a failure. It is a successful profile of an empty column, and §8's coverage matrix needs it present-but-empty to distinguish "cohort never measured this" from "cohort has no such column".

## Not here (nogo)

Do not repair, re-encode or coerce a failing column. Never omit a failed column from the manifest because it looked unimportant.

## Done when

```
nextflow run . -profile test,docker --stop_after profile
test -f results/profiles/_failed.json
```

A deliberately mixed-type fixture column appears in _failed.json with its raw sample, and the run still succeeds.
