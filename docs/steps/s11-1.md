# §11.1 — Project every params row into nextflow_schema.json

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

A magic number inside a process body is invisible to --help, unvalidated, and absent from the manifest's params hash — so a run that used a different value is indistinguishable from one that did not.

## I/O

```
IN   the params tables of §1–§10
OUT  nextflow_schema.json     one property per row, with that exact default
     --help                   generated from it
SIDE nf-schema fails the run on an unknown or out-of-domain param
```

## Contract

```
{ "match_threshold": {
    "type": "number", "default": 12.0, "minimum": 0,
    "description": "Match weight above which two records are one person",
    "help_text": "See schematic §3.3. Lowering this over-links: N shrinks
                  and variance is understated.",
    "fa_icon": "fas fa-link" } }

# The `domain` column becomes minimum/maximum or enum.
# The `effect` column becomes help_text. Neither is optional.
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| validate_params | true | boolean | nf-schema validation; off means a typo becomes a silent default | config |
| schema_ignore_params | [] | string list | every entry is a hole in validation; keep it empty | config |
| params_hash_file | results/params_hash.txt | path | what the manifest and locked_model.json compare | config |

## Alternatives

Seam: ParamStore — get(name) -> value

| alternative | why you'd swap | swap cost |
|---|---|---|
| a YAML params file per cohort | per-cohort overrides without long CLI lines | a second precedence order to reason about, and a hash that must cover both |
| hard-coded defaults in modules | fewer files | violates principle 6; defaults vanish from --help and the manifest |

## Trap

Adding a param to the schema and a different default in the process. nf-schema validates the declared value, the process uses its own, and the manifest records the one that was never applied — a reproducibility bug that reproduces perfectly.

## Not here (nogo)

Do not read an environment variable inside a process. Never add to schema_ignore_params. Do not leave a step's params table unrepresented.

```
nextflow run . --help

```

Every params row in this document appears in --help with its stated default.
