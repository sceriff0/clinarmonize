# §11.2 — Pin containers and emit versions from every process

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

The vocabulary release, the pack and the container digests are the three things that make two runs comparable. A floating tag makes the other two pointless: same manifest, different arithmetic.

## I/O

```
IN   process definitions
OUT  versions.yml per process -> collated into the manifest
     software_versions.yml    -> MultiQC section
SIDE none
```

## Contract

```
container "biocontainers/duckdb:1.1.3--h1234567_0"   # digest-pinned

# NEVER `:latest`, never a bare major tag.
# versions.yml, emitted by every process:
"${task.process}":
    duckdb: $(duckdb --version | sed 's/^v//')
    python: $(python --version | sed 's/Python //')
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| container_registry | quay.io | hostname | where images are pulled from | config |
| singularity_cache | $NXF_SINGULARITY_CACHEDIR | path | image cache on HPC | profile |
| fail_on_floating_tag | true | boolean | a lint step rejecting any unpinned container reference | config |

## Alternatives

Seam: Runtime — the -profile axis: docker | singularity | conda

| alternative | why you'd swap | swap cost |
|---|---|---|
| conda environments | no container runtime on restricted HPC | solver drift; two runs a month apart differ, which pinning was meant to prevent |
| one fat image | a single pull; simpler caching | violates principle 8 and needs an ADR; every process rebuilds on any change |

## Trap

Pinning the image and letting the process pip install at runtime. The digest is then honest about the base and silent about what actually ran, which is the half that changed.

## Not here (nogo)

Never use a floating tag. Do not install anything at runtime. Do not build a bespoke image without an ADR in §15.

## Done when

```
nextflow run . -profile test,docker
grep -c ':latest' modules/**/main.nf    # 0
test -s results/pipeline_info/software_versions.yml
```

Every process contributes a versions entry and no container reference floats.
