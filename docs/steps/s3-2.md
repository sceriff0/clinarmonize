# §3.2 — Score pairs with a Fellegi–Sunter model, missing as its own outcome

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

m and u — agreement given the same person, agreement given different people — turn field comparisons into a log-likelihood ratio that is comparable across fields. Everything about the linkage's honesty lives in whether those two probabilities were estimated or assumed.

## I/O

```
IN   candidate pairs + the cohort's records
OUT  link/scores.parquet  (left_id, right_id, match_weight, per_field_agreement)
     link/model.json      the estimated m and u per field, per level
SIDE none
```

## Contract

```
# Three-way agreement — NOT binary. This is the whole step.
agree | disagree | missing        # missing gets its own m,u pair

match_weight = log2( P(pattern | match) / P(pattern | non-match) )
             = sum_over_fields log2( m_f(level) / u_f(level) )

# link/model.json
{ "field": "birth_date", "levels": [
    {"level":"agree","m":0.94,"u":0.003},
    {"level":"missing","m":0.04,"u":0.05} ] }
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| link_em_iterations | 20 | 1..200 | EM passes estimating m; too few leaves m at its prior | config |
| link_comparison_spec | assets/comparisons.yaml | path | per-field comparison levels, including the missing level | config |
| link_u_from_random_pairs | true | boolean | estimates u by sampling random pairs rather than assuming it | config |
| link_random_pair_n | 1000000 | 10^4..10^8 | sample size for the u estimate | config |

## Alternatives

Seam: PairScorer — score(pair) -> (weight, [FieldAgreement])

| alternative | why you'd swap | swap cost |
|---|---|---|
| deterministic rule cascade | fully explainable; no EM to justify | brittle to typos; no calibrated weight to threshold on |
| a supervised classifier | higher accuracy when labels exist | labels almost never exist, and the training signal is where outcome leakage enters |

## Trap

Folding missing into disagreement. Missingness is a third outcome with its own m and u; collapsing it pushes true matches below the threshold, which looks exactly like under-linkage and gets "fixed" by moving the wrong knob.

## Not here (nogo)

Do not accept or reject a pair — §3.3 owns the threshold. Never include an outcome-flagged column as a comparison field, even when it would help.
