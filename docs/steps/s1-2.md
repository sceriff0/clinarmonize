# §1.2 — Drop held-out datasets at channel construction, not at read time

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

A held-out dataset that reaches a process can be read by a bug. One that was never emitted into the channel cannot. Moving the seal from runtime to graph construction turns "we did not look" from a promise into a property of the DAG.

## I/O

```
IN   ch_datasets (all rows)
     --unseal <dataset_id>   optional, repeatable
     locked_model.json       required IF --unseal is given
OUT  ch_open   : rows with holdout == false, plus any unsealed row
     unseal.log: appended (timestamp, dataset_id, git_sha, params_hash)
SIDE refuses to start when --unseal has no matching locked_model.json
```

## Contract

```
# workflows/harmonize.nf
ch_open = ch_datasets.filter { meta, _ ->
    !meta.holdout || meta.dataset_id in params.unseal
}
# locked_model.json — hashed BEFORE any held-out row is admitted
{ "analysis_git_sha": str, "params_hash": str,
  "locked_at": iso8601, "covers": [dataset_id] }
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| unseal | [] | list of dataset_id | admits named held-out datasets; refuses without a matching lock | CLI |
| locked_model | locked_model.json | path | the lock --unseal is checked against | CLI |
| unseal_log | unseal.log | path | append-only audit trail | config |

## Alternatives

Seam: HoldoutPolicy — admit(Meta, Lock?) -> bool

| alternative | why you'd swap | swap cost |
|---|---|---|
| per-fold rotation (LODO) | leave-one-dataset-out needs each dataset held out in turn, which one boolean cannot express | the flag becomes a fold assignment; the lock must cover a fold, not a run |
| log-only unsealing | simpler; no lock file to manage | records the violation after the damage — a seen number cannot be unseen |

## Trap

Filtering inside the process that reads the table. By then the path is staged, the file is on disk in the work directory, and any later cat in a debug session opens it. The seal has to be upstream of staging or it is decoration.

## Not here (nogo)

Do not let --unseal proceed without a hash-matching lock. Never write the unseal log anywhere the run can overwrite. Do not silently ignore an unknown dataset id.

## Done when

```
nextflow run . -profile test,docker --unseal COHORT_B   # exits 1: no lock
grep -c COHORT_B .nextflow.log                         # 0 staged paths
```

With no lock present the run refuses; unseal.log is unchanged.
