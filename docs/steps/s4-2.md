# §4.2 — Score each candidate on six independent evidence channels

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

One score cannot be argued with; six can. Each channel fails differently, so a disagreement between them is the signal a human reviewer at §5 actually needs — and reporting them separately is what makes the ledger refereeable rather than oracular.

## I/O

```
IN   propose/candidates.parquet + profiles/*.json + pack + vocabulary
OUT  propose/evidence.parquet (candidate_key, channel, score, detail)
     propose/confirmation_plots/<candidate_key>.png
SIDE none — a pure function; this purity is what §10.1 tests
```

## Contract

| channel | signal | the failure it alone catches |
|---|---|---|
| name_similarity | Jaro-Winkler over normalised column names | nothing the others catch — it is the weakest and the most trusted |
| type_agreement | inferred type vs the concept's expected type | an ID column read as a measurement |
| cardinality | unique-count ratio vs expected domain size | a categorical stored as continuous |
| value_overlap | Jaccard of the unique-value set vs the concept's ATHENA value set | a correctly-named column holding a different coding system |
| distribution_distance | Wasserstein vs confirmed columns for the same concept elsewhere | a scale flip that leaves name, type and cardinality intact |
| unit_plausibility | does the range fit the candidate unit, or fit after ×30.4 / ×365.25 | months recorded where days are expected — invisible to all five others |

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| channel_weights | {name:0.15, type:0.15, card:0.1, value:0.3, dist:0.15, unit:0.15} | sums to 1 | the rank order of proposals; never their acceptance | config |
| enabled_channels | all six | enum list | disabling one is recorded in the ledger, not silent | config |
| unit_factor_candidates | [1, 30.4375, 365.25, 0.001, 1000] | float list | the conversions unit plausibility will try | config |
| emit_confirmation_plots | true | boolean | emits the one plot that would kill each proposal | config |

## Alternatives

Seam: EvidenceChannel — score(ColumnProfile, Candidate) -> (float, Detail)

| alternative | why you'd swap | swap cost |
|---|---|---|
| a learned matcher (Ditto-style) | higher top-1 accuracy on benchmark corpora | no per-channel evidence to referee, and the training signal is where outcome leakage enters unobserved |
| a seventh channel: schema context | neighbouring columns disambiguate a bare code column | couples columns, so the permutation test in §10.1 must widen its scope |

## Trap

Six restatements of "the names look alike". Cardinality and value overlap are instance evidence and survive a full rename; name similarity does not survive a translation. If two channels move together under every perturbation, you have five.

## Not here (nogo)

Never let any channel read a column the pack marks outcome: true, directly or through a correlation. Do not accept a proposal. Do not tune weights against a downstream model's performance.
