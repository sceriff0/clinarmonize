# §9.1 — Write the OMOP subset plus the pack-defined extension

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

Standard tables are what make the output readable by tools nobody has written yet (principle 4). The extension exists because a five-table subset cannot hold a pack's derived endpoints without pretending they are observations.

## I/O

```
IN   mapped + derived rows
OUT  results/omop/{person,condition_occurrence,drug_exposure,
                   measurement,observation}.parquet
     results/omop/_extension/<pack>.parquet    pack-defined variables
     results/omop/schema/*.json                published JSON Schema
SIDE none
```

## Contract

results/omop/ ├── person.parquet # person_id, cohort_id, year_of_birth, … ├── measurement.parquet # CDM v5.4 fields + rule_id, rule_version ├── observation.parquet ├── condition_occurrence.parquet ├── drug_exposure.parquet ├── _extension/ │ └── oncology-ici.parquet # endpoint, time_days, event, criteria └── schema/ └── measurement.schema.json # published; consumers validate against it

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| outdir | results | path | where everything lands | CLI |
| emit_extension | true | boolean | writes pack-defined variables outside the CDM subset | config |
| parquet_compression | zstd | zstd|snappy|none | size versus read speed for consumers | config |
| publish_schema | true | boolean | emits the JSON Schema downstream pipelines validate against | config |

## Alternatives

Seam: Emitter — emit(rows, domain) -> Path

| alternative | why you'd swap | swap cost |
|---|---|---|
| load straight into a CDM database | OHDSI tooling works immediately | a database dependency, and the output stops being a file anyone can copy |
| CSV | universally readable | loses types; a partial date becomes a string again |

## Trap

Forcing derived endpoints into observation to stay pure CDM. It makes the output nominally conformant and semantically wrong — an OS time is not an observation, and every consumer then needs the pack to interpret it anyway.

## Not here (nogo)

Do not claim full CDM conformance — this is a documented subset. Never emit a table without rule_id. Do not write a bespoke binary format.
