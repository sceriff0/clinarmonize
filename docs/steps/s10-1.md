# §10.1 — The outcome-permutation harness — the invariant's only proof

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

§0 is a claim about a function's inputs, and the only way to test such a claim is to vary the input that must not matter and observe that nothing changes. Every other check in this pipeline could pass with the invariant violated.

## I/O

```
IN   a fixture cohort set + --permute_outcome_seed 1..N
OUT  N hashes of ledger.proposed.yaml — all identical, or the test fails
     tests/invariant/report.json  {n_permutations, n_distinct_hashes}
SIDE none; runs in CI on every push
```

## Contract

```
# Scope: the PROPOSER, not the whole pipeline. §8.3 legitimately reads
# outcome variables for REPORTING, and reporting is not a mapping
# decision. Testing end-to-end would fail on that and be relaxed.

for seed in 1..100:
    permute outcome column WITHIN each cohort   # preserves marginals
    run  --stop_after propose
    collect sha256(ledger.proposed.yaml)
assert len(set(hashes)) == 1
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| permute_outcome_seed | null | int or range | test-only; permutes within cohort so marginals are preserved | CLI |
| invariant_n_permutations | 100 | 10..10000 | CI uses 100; a release run uses more | config |
| invariant_scope | propose | propose|map|all | widening it is a design change, not a config tweak | config |

## Alternatives

Seam: InvariantProbe — perturb(inputs, seed) -> inputs

| alternative | why you'd swap | swap cost |
|---|---|---|
| static analysis of the call graph | catches the dependency without running anything | misses leakage through a derived or cached intermediate |
| drop the outcome column entirely | strictly stronger — nothing can read it | breaks §8.3's reporting, so it cannot run as the same test |

## Trap

Permuting across cohorts instead of within. That changes each cohort's outcome marginal, so a channel legitimately reading cohort size appears to leak — the test then fails spuriously and gets weakened until it proves nothing.

## Not here (nogo)

Do not relax the assertion to "hashes mostly agree". Never exclude a channel from the harness to make it pass. Do not run it only before releases.
