# §7.3 — Derive best response, recording the criteria version

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

The same scan sequence yields a different best response under RECIST 1.1 and iRECIST. Two cohorts scored under different criteria are not the same variable, and the only place that fact can be recorded is here.

## I/O

```
IN   per-person lesion/assessment rows + pack derivation spec
OUT  derived/endpoints.parquet rows with endpoint = best_response
     (value, criteria_version, n_assessments, confirmed)
SIDE none; a cohort with no assessment rows yields no rows, not a null
```

## Contract

```
best_response ∈ {CR, PR, SD, PD, NE}
criteria_version ∈ {recist_1_1, irecist, who, custom:<id>}

# Under iRECIST, progression requires CONFIRMATION at a later scan;
# under RECIST 1.1 it does not. `confirmed` records which rule ran.
# A cohort supplying a pre-scored response gets
# criteria_version = "custom:source" and is NEVER pooled silently.
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| response_criteria | null | enum | per-cohort; null means the cohort supplies its own scored response | samplesheet |
| require_confirmation | false | boolean | whether PD needs a confirmatory later assessment | pack |
| pool_across_criteria | false | boolean | pooling different criteria into one variable — off, and loud when on | config |

## Alternatives

Seam: ResponseDeriver — bestResponse([Assessment], Criteria) -> Response

| alternative | why you'd swap | swap cost |
|---|---|---|
| accept the source's best response only | no lesion-level data needed; most cohorts have none | criteria become unknown per cohort, so cross-cohort pooling is unjustifiable |
| derive under both criteria, emit both | makes the criteria effect measurable | doubles the response rows; consumers must pick, and most will pick wrongly |

## Trap

Pooling custom:source responses with derived ones. Pseudoprogression means an iRECIST-scored cohort has systematically fewer PD calls, so pooling shifts the response rate by a mechanism that looks exactly like a treatment effect.

## Not here (nogo)

Never emit a response without criteria_version. Do not default an unscored cohort to RECIST 1.1. Do not pool criteria unless explicitly asked.

## Docs

- [RECIST 1.1 (Eisenhauer 2009)](https://pubmed.ncbi.nlm.nih.gov/19097774/)

- [iRECIST (Seymour 2017)](https://pubmed.ncbi.nlm.nih.gov/28271869/)

## Done when

```
nf-test test tests/response_criteria.nf.test
```

One assessment sequence derives PD under RECIST 1.1 and SD under iRECIST, and both rows carry their criteria version.
