# §3.1 — Block candidate pairs so comparison is tractable

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

Comparing every pair is quadratic and unnecessary. Blocking is where the recall ceiling is set: a pair excluded by every blocking rule can never be matched, no matter how good the comparison model is, and no later stage can tell it was excluded.

## I/O

```
IN   a cohort's datasets, one row per patient-record
OUT  candidate pairs (left_id, right_id, blocking_rule_id)
     link/blocking_report.json  { rule_id, n_pairs, n_records_unblocked }
SIDE none
```

## Contract

```
# assets/blocking_rules.yaml — a LIST; recall is their union
- id: br_dob_sex   on: [birth_date, sex]
- id: br_name3     on: [substr(last_name,1,3), birth_year]
- id: br_mrn       on: [mrn]

# blocking_report.json records n_records_unblocked — records no rule
# ever placed in a block. That number is the recall ceiling's shadow.
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| blocking_rules | assets/blocking_rules.yaml | path | the rule list; their union sets maximum recall | config |
| max_block_size | 10000 | 100..10^6 | a block larger than this is reported and skipped, not silently expanded | config |
| max_pairs_warn_frac | 0.1 | 0.0..1.0 | warns when candidate pairs exceed this fraction of the full cross product | config |

## Alternatives

Seam: Blocker — block(records, rules) -> [CandidatePair]

| alternative | why you'd swap | swap cost |
|---|---|---|
| sorted neighbourhood | degrades gracefully on typos at a key's head | a window parameter that is harder to justify than a rule list |
| locality-sensitive hashing | no hand-written rules at all | recall becomes opaque; the ceiling stops being inspectable |

## Trap

Choosing rules by how many pairs they produce. The rule that produces the fewest pairs is usually the one excluding the hard cases, and a match-weight histogram with no overlap region is that mistake showing up as an apparently clean result.

## Not here (nogo)

Do not score, threshold or decide anything. Never let a blocking rule reference the outcome variable or any column the pack marks outcome: true.

## Done when

```
nextflow run . -profile test_full,docker --stop_after block
jq -e '.[] | .n_records_unblocked' results/link/blocking_report.json
```

Every rule reports its pair count and the unblocked-record count is present, even at zero.
