# §2.1 — Profile every column into a typed evidence record

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

Every downstream evidence channel reads exactly one field of this record. Fixing the record's shape here fixes what the matcher is capable of noticing, so the field list is a design decision about detection power, not a convenience.

## I/O

```
IN   [ meta(cohort_id, dataset_id), path(table) ]
OUT  profiles/<cohort_id>.<dataset_id>.json   one record per COLUMN
SIDE none — a pure function of the table bytes and the params below
```

## Contract

```
# modules/local/profile_columns/main.nf -> profiles/*.json
{ "column": str,                  # verbatim source name, never normalised here
  "inferred_type": "int|float|str|date|bool|empty",
  "n_rows": int, "n_missing": int, "n_unique": int,
  "unique_values": [str],         # the SET, capped; null when over cap
  "unique_truncated": bool,       # explicit: absence != "few values"
  "quantiles": [float],           # p0 p1 p25 p50 p75 p99 p100; numeric only
  "candidate_units": [str],       # parsed from the header, UCUM-normalised
  "example_values": [str] }       # first k non-missing, for the ledger
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| max_unique_listed | 500 | 1..100000 | caps the stored unique-value set; over it, sets unique_truncated | config |
| date_formats | ["%Y-%m-%d","%Y-%m","%Y"] | strftime list | what parses as a date — and therefore what becomes a partial date in §7.1 | config |
| example_k | 5 | 0..50 | example values carried into the ledger for the human gate | config |
| na_strings | ["","NA","NULL","."] | string list | what counts as missing; wrong here inflates cardinality everywhere | config |

## Alternatives

Seam: Profiler — profile(table) -> [ColumnProfile]

| alternative | why you'd swap | swap cost |
|---|---|---|
| DuckDB SUMMARIZE | out-of-core on tables that exceed RAM | no unique-value set without a second query |
| ydata-profiling | rich stats and an HTML report for free | heavy dependency; slow on wide clinical tables |
| Polars describe | fastest in-memory path | quantile semantics differ from DuckDB's; pin one |

## Trap

Storing cardinality and dropping the unique-value set. Cardinality says a column has five values; the set says they are {CR,PR,SD,PD,NE}, which is what identifies a RECIST column against a concept's value set. Only the set survives a full rename.

## Not here (nogo)

Do not normalise, lowercase or strip the column name — §4.1 needs it verbatim. Never drop a column that fails to parse; §2.3 manifests it. Do not read the outcome column differently from any other.
