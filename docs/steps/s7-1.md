# §7.1 — Normalise dates, keeping partial dates partial

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

Clinical dates arrive as year, year-month and full dates in one column. Silently completing a partial date to the first of the month invents precision that then propagates into every interval, and nothing downstream can see that it was invented.

## I/O

```
IN   mapped rows with date-typed columns
OUT  same rows + (<col>_date, <col>_precision) where precision ∈
     {day, month, year}; the imputed date is ALWAYS accompanied by it
SIDE none
```

## Contract

```
"2021-03-14" -> (2021-03-14, day)
"2021-03"    -> (2021-03-15, month)   # mid-interval, not the 1st
"2021"       -> (2021-07-01, year)    # mid-interval

# Mid-interval, because month-start systematically biases every
# interval in one direction; mid-interval biases variance instead.
# All timestamps are stored naive UTC dates — no local time, ever.
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| partial_date_policy | mid_interval | mid_interval|start|reject | how a year- or month-only date becomes a date | config |
| min_date_precision | month | day|month|year | coarser than this and the row is excluded from derivation | config |
| reject_future_dates | true | boolean | a date after the run date is a data error, not a censoring time | config |

## Alternatives

Seam: DateNormaliser — parse(str) -> (date, Precision)

| alternative | why you'd swap | swap cost |
|---|---|---|
| interval-censored derivation | statistically correct: a month-only date IS an interval | every downstream model must accept interval censoring; most do not |
| reject partial dates outright | no invented precision at all | discards whole cohorts — registry data is routinely month-only |

## Trap

Dropping the precision column once a date exists. Precision is what lets §8 report how much of a cohort's survival time is imputed, and without it a month-only cohort is indistinguishable from a day-precise one in every plot.

## Not here (nogo)

Do not apply a timezone. Never impute a date without emitting its precision. Do not infer a missing date from another row.
