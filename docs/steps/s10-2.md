# §10.2 — Module and pipeline tests on two public fixtures

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

Eunomia is native OMOP and tiny — perfect for CI, and useless for proving the pipeline handles mess. MIMIC-IV demo is genuinely messy with many tables per subject, which is the real JOIN-then-UNION shape. Both are needed and neither is oncology.

## I/O

```
IN   -profile test       -> Eunomia          (CI, every push)
     -profile test_full  -> MIMIC-IV demo    (nightly; multi-centre
                                              exercised as multi-cohort)
OUT  nf-test snapshots + versions.yml from every process
SIDE none
```

## Contract

tests/ ├── ingest.nf.test # §1.1 duplicate key rejection ├── link_score.nf.test # §3.2 three-way agreement ├── propose_channels.nf.test # §4.2 per-channel behaviour ├── units.nf.test # §6.2 analyte-specific factors ├── endpoints_inverted.nf.test# §7.2 rising-KM detection ├── invariant.nf.test # §10.1 — the one that matters └── generality.nf.test # §10.3

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| test_data_base | nf-core test-datasets URL | url | where fixtures are fetched from | profile |
| max_memory | 6.GB | memory | keeps -profile test runnable on a laptop and in CI | profile |
| snapshot_update | false | boolean | regenerates nf-test snapshots; never true in CI | CLI |

## Alternatives

Seam: Fixture — load(profile) -> [CohortDir]

| alternative | why you'd swap | swap cost |
|---|---|---|
| a synthetic generator | every failure mode on demand, no download | synthetic data never surprises you, which is the point of a real fixture |
| full MIMIC-IV | realistic scale | credentialed access, so CI cannot run it and the fixture stops being public |

## Trap

Using Eunomia alone because it is already OMOP. It never exercises §4 or §6 in earnest — its columns are already mapped — so a matcher can be badly broken and CI stays green.

## Not here (nogo)

Do not add an oncology fixture as the primary test. Never commit fixture data to the repo. Do not update a snapshot to make a failing test pass.
