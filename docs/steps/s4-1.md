# §4.1 — Generate candidate concepts from the pinned vocabulary

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

Scoring every column against every concept is intractable and pointless. Candidate generation bounds the work and, like blocking in §3.1, sets a recall ceiling that no later scoring can lift — so what it excludes must be recorded.

## I/O

```
IN   profiles/*.json + the concept pack + the pinned ATHENA release
OUT  propose/candidates.parquet (cohort_id, dataset_id, column,
                                 variable, concept_id, generator_id)
SIDE none; a column with zero candidates is emitted with a null concept_id
```

## Contract

```
# assets/packs/<name>.yaml — the pack IS the target variable set
pack: oncology-ici
version: 1.2.0
vocabulary: athena-2026-08          # pinned release; hashed
variables:
  - name: ecog
    domain: observation
    concept_id: 4265453
    type: ordinal
    domain_values: [0, 1, 2, 3, 4]
  - name: os
    domain: derived
    derivation: survival_time
    unit: day
    outcome: true                   # excluded from EVERY channel (§4.2)
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| max_candidates_per_column | 20 | 1..500 | the recall ceiling; excluded candidates are counted in the ledger | config |
| candidate_generators | [name_ngram, value_set, unit] | enum list | which cheap generators propose candidates at all | config |
| vocabulary_release | — | release id | pins ATHENA; a change invalidates every confirmed ledger row | pack, required |

## Alternatives

Seam: CandidateGenerator — generate(ColumnProfile, Pack) -> [Candidate]

| alternative | why you'd swap | swap cost |
|---|---|---|
| embedding retrieval over concept names | catches synonyms and translations no n-gram will | a model container, and a recall ceiling nobody can inspect |
| full cross product | no recall ceiling at all | quadratic in concepts; unusable against a full ATHENA release |

## Trap

Generating candidates from the concept's name alone. Clinical column names are institution-local (VAR_0114) and the value set is often the only signal present — a generator list without value_set silently loses those columns.

## Not here (nogo)

Do not score or rank — §4.2 owns that. Never generate a candidate for a variable the pack marks outcome: true. Do not fall back to an unpinned vocabulary.

```
nextflow run . -profile test,docker --stop_after propose
duckdb -c "select count(*) from 'results/propose/candidates.parquet'
           where variable in (select name from pack where outcome)"
```

That count is zero: no outcome variable ever receives a candidate.
