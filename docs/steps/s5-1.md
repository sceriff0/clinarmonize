# §5.1 — Accept a confirmed ledger and refuse to guess when it is absent

> Extracted verbatim from `docs/schematics/p-harmonize.html`.
> Per §0.2: read §0 and this card. Read nothing else.

## Why

The gap between proposed and confirmed is where the human judgement lives. A pipeline that fills that gap with its own top-ranked guess has quietly deleted the only review step in the design while still emitting a file called a ledger.

## I/O

```
IN   --confirmed_ledger ledger.confirmed.yaml   (required to pass §5)
     ledger.proposed.yaml                        (for the staleness check)
OUT  ch_confirmed : [ cohort_id, dataset_id, column, variable, concept_id, rule_id ]
SIDE exits non-zero, with the diff, when the confirmed ledger is stale
```

## Contract

```
# ledger.confirmed.yaml — proposed + a decision + who + why
- cohort_id: COHORT_A
  dataset_id: clinical
  column: "PDL1_PCT"
  decision: accept              # accept | reject | remap | defer
  variable: pdl1_tps
  concept_id: 4245277
  unit_in: "%"                  # the resolved unit; §2.2 only ranked them
  confirmed_by: "a.reviewer"
  rationale: "value set 0-100, LOINC 83052-1 matches assay note"
  proposed_hash: "sha256:9f21…"  # staleness guard
```

## Params

| name | default | domain | effect | set by |
|---|---|---|---|---|
| confirmed_ledger | null | path | the human gate; null stops the run after §4 with instructions | CLI |
| require_rationale | true | boolean | an accept with no rationale is rejected at parse time | config |
| allow_stale_ledger | false | boolean | escape hatch when a pack bump did not change proposals; logged loudly | CLI |

## Alternatives

Seam: ConfirmationSource — confirm([Proposal]) -> [Decision]

| alternative | why you'd swap | swap cost |
|---|---|---|
| Usagi export | a real reviewer UI with vocabulary search built in | an import shim, and Usagi's model has no cohort dimension |
| auto-accept above a score | unblocks CI and demos | deletes the gate; permitted ONLY under -profile test, never in a release run |

## Trap

Matching confirmed rows to proposals by row index. A pack bump reorders proposals and the ledger silently re-points every decision at a different column. Match on (cohort_id, dataset_id, column) and verify proposed_hash.

## Not here (nogo)

Do not auto-confirm outside -profile test. Never proceed past a stale proposed_hash without --allow_stale_ledger. Do not edit the proposed ledger in place.

## Done when

```
nextflow run . -profile test,docker            # no ledger: stops after propose
nextflow run . -profile test,docker --confirmed_ledger assets/test_ledger.yaml
```

Without a ledger the run stops cleanly and prints the path to write; with one it proceeds.
